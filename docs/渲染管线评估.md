# 渲染管线评估

审查对象：仓库全部 `src/*.js`（32 个文件）中所有 `WebGLRenderer`、rAF 主循环与资源构建路径。
结论：**管线不算过度复杂，不需要合并成一个 renderer。真正的开销在「同一份 3D 资源被建两遍」和「面板挡住世界时世界仍满帧渲染」。**

## 1. 结论速览

| 问题 | 是否成立 | 依据 |
|---|---|---|
| WebGL 上下文太多会爆 | ✗ 不成立 | 峰值同时 3 个，上限 8–16；且每个 dispose 都调 `forceContextLoss()` |
| 需要合并成单 renderer + 多 scene | ✗ 不建议 | 收益只是 3→1 个上下文，代价是布局与渲染耦合、状态串味 |
| 存在每帧重建几何/材质 | ✗ 基本没有 | 重建点都有 key 守卫（详见 §3） |
| 面板打开时仍在渲染被遮住的世界 | ✓ 成立 | 已修，见 §5 |
| 同一场景 glTF / 工作台模型被解析构建两遍 | ✓ 成立 | 见 §4，尚未修 |
| 每帧无效分配与样式重算 | ✓ 成立 | 量级小，见 §6 |

## 4. 重复资源（真正的浪费）

| 重复点 | 证据 | 量级 |
|---|---|---|
| 同一场景 glTF 解析两遍 | `scene-environment.js:12` 每次 `new GLTFLoader().parseAsync(...)`，被主世界与预览世界各调一次 | 2× 2.69MB 解析、2× buffer 上传 |
| 6 个工作台模型建两套 | `world.js:190-192` 两个 world 都执行 | 2× 194 网格 / 48,213 三角 |
| 瓷碗缩略图每张一个上下文 | `decals.js:163`（已修） | 4 次上下文创建 ≈ 4×200ms 卡顿 |
| 招牌 CanvasTexture 每次切场景新建 | `world.js:249` | 1024×240 × 4 张（带 mipmap） |
| ✅ 材质缓存跨 world 共享 | `world.js:14-15` `mats` Map + 白名单 | 只建一份 |
| ✅ 贴花纹理模块级缓存 | `decals.js:5` | 4 张只生成一次 |

实测规模（Node 导入模型 + 解析 GLB，只读）：`guyao` 69,580 三角 / 30 网格；`museum` 54,828；`imperial` 47,534；`taoxichuan` 93,130。工作台合计 194 网格 / 48,213 三角 / 72 材质。加顾客、玩家、24 颗独立 dust 网格，主世界约 **320 draw call / 12–13 万三角每帧**。

## 5. 本次已实施

1. **面板打开时停掉世界渲染** — `main.js:325`：
   ```js
   if(started&&!activeTask&&!helpOpen)world.update(dt,t,state,playing);
   ```
   面板都是 `inset:0` + `backdrop-filter:blur(6px)` 的覆盖层（`style.css`），此前世界仍在满帧渲染并让那层模糊反复取背景。面板期省掉整帧 320 draw + 2048² 阴影 pass，回来时 `dt` 已被 `main.js:315` 夹到 0.05，不会跳帧。
2. **瓷碗缩略图复用一个 renderer** — `decals.js:162-168`：新增 `setBowl(index)`（`decals.js:159`），`bowlImage` 全程复用一个离屏 preview。4 件藏品从 4 次「建上下文 + 生成 PMREM + 销毁」压到 1 次。
3. **`prefers-reduced-motion` 查询提到实例级** — `world.js:263`：原来每帧 2–3 次 `matchMedia()`（每次新建 MediaQueryList），现在缓存一次。

实测（msedge headless，vite dev）：
- 面板打开期间主世界渲染帧数增量 **0**，关闭后 600ms 内恢复 **66 帧**（约 110fps）。
- 4 张缩略图 URL 互不相同（4/4 唯一），页面无 console error。

## 6. 后续可选（按收益/风险排序）

| # | 改动 | 收益 | 风险 |
|---|---|---|---|
| 1 | 预览世界复用主世界的 glTF（`scene-environment.js` 单例 parse → clone）与工作台网格 | 省一次 2.7MB 解析 + 96k 三角重复构建 | 中：`disposeWorldTree` 的共享/独占所有权要区分 |
| 2 | 升级页加脏标记，hover 时复用模型而非重建 | 去掉每帧 2 次全场景渲染与抖动 | 低 |
| 3 | 阴影 `shadowMap.autoUpdate=false`，角色移动时置 `needsUpdate` | 省每帧 2048² 阴影 pass | 中：漏标记=影子拖影 |
| 4 | `world.js:260-261` Vector3 池、`main.js:319-320` 只在值变化时写 dataset/style | 每帧 ~10 次分配 + 6 次样式重算 | 低 |
| 5 | 删死代码：`src/landmarks.js` 整文件无人 import；`world.js:113-131` 五个构造器无调用点 | 运行时零收益，纯维护负担 | 无 |

**不建议**：合并成单 renderer。renderer 绑死单个 canvas，而 7 个视图分布在 3 个不同 DOM 位置；合并要么让 CSS 布局与 `setScissor` 耦合，要么每帧多一次 RenderTarget 拷贝；各视图还要手工复原 dpr（1.5/1.75/2）、exposure（.94/1/1.02）、阴影开关、`preserveDrawingBuffer`。换来的是 3→1 个上下文和一个本来就不存在的瓶颈。
